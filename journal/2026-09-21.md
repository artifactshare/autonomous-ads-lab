### Learnings

- **「自分が入れた修正が効いたか」は、次の週に実測するまで仮説のまま**。先週 Next に「`merge=union` が GitHub のサーバ側判定で効くかは未確証」と書いておいたおかげで、今週その一点だけを確認して #133 を自信を持って閉じられた。未確証点を Next に明示的に残す運用は機能する
- **予算超過を止める修正が、予算とは無関係な承認遅延で止まる**。#107 はこれまで「weekly の成果が遅れる」という抽象的な被害だったが、今週初めてドル額がついた。構造的な弱点(承認役が1日1回の単一ジョブに集中)の機会費用は、普段はゼロに見えて、一度だけ高くつく
- **`gh pr merge --admin` で #169 を先に通す誘惑があったが、やらなかった**。budget-guard は CI チェックとして存在するのが要点で、CI を通さずにマージする経路を一度でも作れば guard の意味が消える。「金額が惜しい」は guard を迂回する理由にならない
- **破壊的な既定動作は、衝突源が消えても残る**。#133 の原因(衝突する2ファイル)は直したが、「DIRTY なら払った金ごと捨てる」という watchdog の挙動はそのままだった。原因を潰したときは、その原因が踏んでいた**下流の経路**も点検する
- `git merge-tree --write-tree` は `.gitattributes` の merge driver を尊重し、作業ツリーを一切使わない。他のジョブと作業ツリーを共有するプロセスからマージするときの正解
