## 1. X動画広告の技術要件と公式推奨

### 技術仕様（confidence: high — X公式）
- 尺: 推奨 **15秒以下**（最大 2分20秒）。15秒以下が完了率・ブランド効果ともに最良
- アスペクト比: **1:1 推奨**（デスクトップ/モバイル両方で常に正方形描画）。9:16 も 1:1 と同じフィード占有面積で、16:9 より大きい
- 解像度: 1:1 なら 1200x1200 推奨（最小 600x600）
- ビットレート: 6,000〜10,000k（1080p は 6,000k 推奨）、29.97/30fps（60fps まで可）、H.264 / 4:2:0
- 出典: https://business.x.com/en/help/campaign-setup/creative-ad-specifications

### 公式のクリエイティブ推奨（confidence: high）
- **無音前提**: フィードではミュート自動再生。字幕またはテキストオーバーレイ必須級
- 字幕・視覚的キューのある15秒広告は、30秒広告比で**完了率3倍**
- **ブランド要素は冒頭3秒以内**に。ロゴは左上に常時表示 → **想起 +36%**（視聴時間への悪影響なし）
- ブランド指標インパクトの**70%は冒頭3秒**で決まる。メッセージを3秒以内に伝えると突破指標 +13%
- 冒頭数秒に「動き」か「人物」を入れて注意を掴む
- モバイル最適化されたベストプラクティス準拠動画は感情エンゲージメント +33%
- 出典: https://business.x.com/en/advertising/creative-best-practices / https://business.twitter.com/en/blog/video-advertising-best-practices.html

### 実務上の含意
- デフォルト設計: **1:1・15秒以下・無音で意味が通る・ロゴ左上常時・字幕焼き込み**
- 音声はあくまで加点要素。ナレーション依存の構成は作らない

## 2. 冒頭3秒のフック設計パターン

背景となる研究（confidence: medium、プラットフォーム公式研究含む）:
- Facebook–Nielsen: 3秒以下の視聴でも想起 +47% / 認知 +32% / 購入意向 +44%。Meta: 0.25秒露出で有意な想起、モバイルフィードの平均滞在は1.7秒
- TikTok×Kantar（3,500本分析）: **想起インパクトの90%は最初の6秒**で獲得
- Meta Reels: 最強クリエイティブはフックを**1.5秒以内**に置く
- Nielsen視覚注意研究: 冒頭3秒に3回以上のシーンチェンジがある動画は完了率 +58%
- 出典: https://martech.org/even-brief-video-views-drive-brand-lift-facebook-nielsen-study-finds/ / https://coinis.com/glossary/hook-rate / https://yume.video/blog/write-video-ad-hooks-that-stop-the-scroll

フック型カタログ（confidence: medium）:

| パターン | 例（開発者SaaS向け） |
|---|---|
| 問題直撃質問 | 「デプロイのたびにSlackで報告書いてない？」 |
| 数字の断言 | 「レビュー依頼が30秒で終わる」 |
| Before提示 | 崩れたスクショ共有画面 → 一拍おいて解決 |
| 動作中の画面 | いきなりコマンド実行、結果が出る瞬間から始める |
| 逆張り宣言 | 「スクショ共有、もうやめました」 |
| 途中から見せる | 完成直前の操作から開始し「どうやったか」を続ける |
| テキスト爆速提示 | 大きな文字1行を0.5秒で切り替え×3 |

原則: 1.5秒以内に視覚変化、3秒以内に「誰の何の話か」が伝わる。フック=サムネイル（静止した1フレーム目でも成立させる）。

## 3. 短尺で使える映像表現技法カタログ

（confidence: medium。映像技法自体は確立された通説、5秒適用は一部 low）

- **モンタージュ（高速カット羅列）**
  - 効果: 短時間で「多機能・スピード感」を圧縮伝達。カット密度が注意を維持
  - 5秒適用: 0.5〜0.8秒×5カットで利用シーンを羅列 → 最後1秒でロゴ+一言
- **ジャンプカット**
  - 効果: 待ち時間・冗長動作の省略。テンポの人工的加速
  - 5秒適用: 操作の途中経過を全部飛ばし「コマンド→完了」だけ見せる。カット時に約20%ズーム変化を入れると違和感が減る（"covering the cut"）
- **パターン中断（pattern interrupt）**
  - 効果: 注意のリセット。5〜7秒ごとが目安、5秒広告なら中間1回
  - 5秒適用: 2.5秒地点で急ズーム/色反転/効果音的テキスト。5秒間「何も変化しないブロック」を作らない
  - 出典: https://joyspace.ai/pattern-interrupt-reset-attention-span
- **Before/After**
  - 効果: 価値の瞬間理解。説明不要で差分が伝わる
  - 5秒適用: 画面2分割 or 2秒Before→カット→2秒After→1秒CTA。Beforeは誇張気味に「面倒さ」を可視化
- **ループ構造**
  - 効果: 終端と冒頭を繋げ、自動リピート再生で視聴回数・理解度を稼ぐ
  - 5秒適用: 最終フレーム=1フレーム目と同構図。「終わった感」を出さず気づいたら2周させる
- **視線誘導**
  - 効果: 見せたいUI要素へ確実に注意を運ぶ
  - 5秒適用: ズームイン、カーソル動線、周辺減光、矢印/ハイライト。1カット1注目点。ロゴ左上・字幕下段と干渉しない位置に
- **6秒バンパー原則（YouTube由来）**
  - 効果: 「1アイデア・1ビジュアル・1ブランド」に絞ると超短尺でも成立
  - 5秒適用: 伝えることを1つに削る。2つ言いたければ広告を2本作る
- **ABCD フレームワーク（Google）**: Attract（5秒以内に注意）/ Brand（早期ブランディング）/ Connect(視聴者の状況に接続) / Direct（明確なCTA）— 構成チェックリストとして使う
  - 出典: https://www.stackmatix.com/blog/youtube-ads-creative-practices （ABCD自体はGoogle公式: confidence high）

## 4. 開発者向けSaaS特有の注意点

（confidence: medium〜low。事例観察ベース）

- **実物のUI/ターミナルを見せるのが最強のフック**。抽象的なアニメやストック映像は開発者に刺さらない。Stripe/Figma/Notion系の成功例は「クリーンな画面収録+速いシーケンス」でナレーション非依存
- **製品に語らせる**: 機能説明のブレットより「実際の操作が完了する瞬間」。デモ視聴者は購入確率 1.81倍という報告あり
- **画面収録の品質=製品品質のシグナル**。雑な収録+フリー音楽の海の中で、丁寧なモーション・トリム・ズームが差別化になる
- **誇大表現は逆効果**: 開発者はマーケ臭に敏感。断言は検証可能な事実（コマンド1つ、30秒、無料 等）に限定
- **ペルソナ別に型を分ける**: 開発者=API/CLI/所要時間、マネージャ=チームの手間削減。1本で両方狙わない
- **X特有**: 開発者はXに多いがフィード消費は高速・皮肉耐性高。「広告っぽくない、普通の開発Tipsツイートに見える」トーンが有利（confidence: low）
- 出典: https://www.superside.com/blog/saas-video-examples / https://www.moonb.io/blog/saas-product-demo-video

## 5. 5〜15秒広告の推奨テンプレート（統合）

**5秒ループ型**: [0-1.5s] 問題 or 操作開始（大テキスト+動き）→ [1.5-3.5s] ジャンプカットで完了の瞬間 → [3.5-5s] ロゴ+CTA一言、最終フレームは冒頭と接続。
**15秒デモ型**: [0-3s] フック（Before/断言、ロゴ左上イン）→ [3-10s] 画面収録モンタージュ（1カット1機能、ズームで視線誘導、字幕常時）→ [10-13s] After/結果 → [13-15s] CTA。7秒付近にパターン中断を1回。

チェックリスト: 無音で意味が通るか / 1フレーム目がサムネとして成立するか / 3秒で誰向けか分かるか / ロゴ左上か / 伝えたいことは1つか / 5秒無変化ブロックがないか。

## 6. 実録デモを広告に仕上げる作法（2026-09-14 追記、実務者調査）

出典: X の制作者投稿(@titouangillet_ の高視聴動画の分解、@DerekFeehrer / Kite、@Nexaabyraj、@builtbycem、@UtdAce8、@pulsepixtv)、Screenify / Screen Studio の解説、X 広告の 2026 年スペック記事。生データは private `operations/marketing-research/results/2026-09-demo-ad-craft-2026-09-14.md`。
confidence は各行に付す。

### 構造(confidence: medium、複数の制作者が一致)
- **[Hook] → [Demo: 1 つのユースケース] → [End result] → [CTA]**。これ以外を足さない。問題説明は最小、実演を最大にする
- 尺は **15〜30 秒**。1 ビート 2〜3 秒、ビートごとに 1 アクション
- 冒頭 3 秒で価値の約半分が決まる。hook は「製品ショット」でなく **痛み・証拠の数字・未解決の問い・視覚的な pattern interrupt** のどれか。黒画面にテキストだけの 2 秒は「静止」に見えるので、hook の裏でも映像を動かす
- 終わりは **1 行のタグライン + ロゴ/URL** を数秒静止。機能のおさらいはしない

### 画面収録の「dressing」(confidence: medium)
- 生の画面収録は「素人」に見える、が共通認識。必ず **ズーム/リフレーム、コールアウト、ハイライト**を重ねる。クリック位置へ寄って、終わったら引く(Screen Studio 型の auto-zoom が 2026 年の標準)
- **カーソル規律**: 直線で動かす、クリックの 0.5 秒前に止まる、クリック後 1 秒止まる、強調のために振らない(@builtbycem)。合成カーソルなら spring で補間
- UI が密な場面ほどズームが効く。**スマホ幅(約 360px)で文字が読めるか**を必ず確認する。分割画面で 2 つを同時に見せない
- ブラウザのタブ・URL 欄・ターミナルのプロンプトのパスは映さない。製品名は AS のヘッダかロゴで常時見せる(公式推奨: ロゴ左上で想起 +36%)

### 文字と音(confidence: medium)
- **kinetic text で pacing reset**: 実演シーンの間に「You ask:」「Same URL.」のような短い文字カットを挟み、UI 疲れを切る。字幕は説明文でなく広告の言葉(3〜5 語)
- 字幕は焼き込み、大きく、高コントラスト、1〜2 行、中央か下 1/3。自動生成に頼らない
- 無音で意味が通る設計を前提にしつつ、**音は「盛り上がりの半分」**(@pulsepixtv)。歌なしの BGM + クリック/送信/成功の SFX 3 種、音量に抑揚をつける
- ナレーション依存にしない(公式推奨と同じ)

### 縦横比とフィード(confidence: medium)
- X フィードは **1:1 か 4:5**。9:16 は縦動画面に載るときだけ。16:9 はモバイルで小さく、うちの v1 が読めなかった主因
- 重要な文字・ロゴ・CTA は中央 80〜90% に収める(UI の重なりとトリミング対策)

### 切るもの(confidence: medium)
- 核の 1 文に効かないものは全部切る(気に入っていても)。カーソルの迷い、繰り返し、長い説明、弱いトランジション、効果の使い過ぎ
- 「全部速くする」ではなく **緩急**(早送り / 等速 / スロー)とジャンプカット

### うちの v1(2026-09-14、creatives 9〜12)が満たしていない項目
1. 16:9 の上下分割 → スマホで文字が読めない(1 画面 1 要素、4:5 へ)
2. カメラが固定 → クリック位置へのズーム/引きがない
3. ブラウザ/ターミナルの生の枠と説明調の字幕 → dressing と kinetic text
4. 無音、黒背景の hook カード 2 秒 → 動く hook と SFX/BGM
5. end カードに製品の一言が無い(URL のみ) → タグライン 1 行 + ロゴ

評価器(Gemini)にも「360px 幅で読めるか」「1 画面 1 要素か」「クリック点に寄っているか」を項目として足すこと(未実装)。

## 7. キーフレーム駆動の生成 (2026-09-14, 実測 + X 調査, confidence: medium)

- 生成動画モデル (MiniMax H3 Max Turbo) は「start/end 静止画を渡して補間させる」使い方だとガチャがほぼ消える。静止画は Playwright で HTML から決定論的に作る (ブランドトークン、実 URL、本物の数字)。ショットは start→end の差分を 1 種類に絞る。順序のあるアニメは別ショットに割る (順序は無視される)。
- 小さい文字は必ず化ける。読ませたい要素は 360px 幅換算で読める大きさに寄せ、文書全体は等倍で置かない。半透明の背景文書は評価器にも人にも「壊れた画像」に見える。
- 明るいフィードでは暗い hook が pattern interrupt になる。CTA は end フレームをクローン延長して 1 秒以上静止させる。
- 費用は 768P で $0.01/秒 (2026-09-14 まで 75% off、以後 $0.04)。7 ショット 5 秒で $0.35。ショット単位で引き直せる。
- 評価器 (gemini-video-v2-feedwidth) は 5fps サンプルでフリップ途中や着弾途中を「歪み」と読む。その指摘は無視し、「文字化け」「壊れた画像」だけ直す。手順の正本は private skill `keyframe-motion-ad`。
